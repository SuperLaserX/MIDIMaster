# Alesis Wedge: MIDI implementation from the W1 v1.02 firmware

Source: `Alesis Wedge (W1 v1.02 2-31-0077 06-30-97) [TMS27C512].zip` in the firmware collection
(64 KB, 8051 code; "ALESIS WEDGE" at 0x0074). All addresses below are in that image. The editor is
`js/devices/defs/alesis-wedge.js`; its tables (`alesis-wedge-fw.js`) are generated by
`tools/alesis/wedge_fw.py`, which reads the configuration descriptors and runs every parameter's
display routine in a small 8051 emulator (`tools/alesis/i8051.py`):

    python -I tools/alesis/wedge_fw.py "<image .bin>" > js/devices/defs/alesis-wedge-fw.js

**Not checked on hardware** (no Wedge is connected). The tests run against the definition's
simulator, which follows the receiver described here.

## The display

The Wedge has a custom LCD: one 24-character text line (XRAM page 20h, written by 0x0683) and,
under the four sliders A-D, four numeric fields of three 7-segment digits with decimal points, a
bar graph and unit icons (segment set/clear at 0x07B3 / 0x07D8, segment map 0x0FB5, digit
segment groups 0x0550, digit font 0x09A1). The unit icons are lit through small tables beside
their routines: % (190+c), k (198+c), Hz (202+c), m (206+c), s (210+c), decimal points 30+23c and
22+23c (c = slider column). The firmware holds no text for the icons: the editor writes them as
% / kHz / Hz / ms / s, as the manual prints the ranges ("000-500 ms", "029 Hz - ... kHz, OFF").
Words drawn in 7-segment letters are decoded the same way (OFF, On, Sin, tri, FSt, SLo, rEu,
For, bnd, AFt, not, UEL).

## Configurations

28 descriptors of 70 bytes at 0xF856 (index = program byte 1):

| Offset | Content |
|---|---|
| +03h | Name, 11 characters (ROOM+CHORUS, ROOM+HALL, PLATE, HALL REVERB, AMBIENCE, CHAMBER, NONLINEAR, CHORUS~ROOM, MONO DELAY, LARGE PLATE, PINGPONGDLY, MULTI TAP, ROOM+FLANGE, STEREO ROOM, QUAD CHORUS, ROOM+PLATE, ROOM~FLANGE, CHRS/FLANGE, LEZLIE~ROOM, QUAD PITCH, LARGE HALL, FLNG~DLY~RM, DELAY:DELAY, DELAY~ROOM, PLATE+HALL, ROOM REVERB, ROOM+DELAY, CHRS:CHRS) |
| +0Eh | Pages of the second effect (bit per page; 0x2225 copies the bit for the shown page into flag bit 6) |
| +12h | 6 page masks: low nibble = sliders A-D in use, high nibble = an extra icon per column (0x07FB) |
| +18h | 6 page titles: high nibble = first character in the name, low nibble = length ("ROOM", "CHORUS") |
| +1Eh | The 24 parameter maxima (the receiver's limits too) |
| +36h | Page table: 32 bytes per page, a 24-character heading (4 columns of 6) and 4 pointers to the 24-character long names shown while a slider moves |
| +42h | Per-parameter routines that update the DSP |
| +44h | Per-parameter display routines (one of 33 formats; table 0x2299 calls them with R1 = the value's address and 72h = column) |

Parameter i (0-23) is page i / 4, slider i mod 4. The editor labels it with the column heading
(the long name as help, or as the label when the heading is blank), after the page title when a
configuration has two or three effects ("ROOM Decay", "CHORUS CMix"), and lists every value with
the text its display routine shows (for example Decay 1.33 s to 229 s, LPF 029 Hz to 41.3 kHz then
OFF, PDly 000-250 ms, Dens 000-100%, bipolar amounts -50 to 50, waves Sin / tri). Parameters with a
maximum of 0 or on an unused slider are not shown: no routine or page uses them.

## Programs

38 bytes; 128 presets at 0x4E0B, the user bank's reset contents at 0x610B (100 programs) plus the
"BlankProgram" at 0x6FE3, copied 28 times (loops at 0x360F and 0x3629: the second reloads its
source address each time).

| Byte | Content |
|---|---|
| 0 | Edit position: page x 4 + slider shown when the program is recalled; a parameter change sets it (0x1DB3) |
| 1 | Configuration 0-27 |
| 2-13 | Name, 12 characters |
| 14-37 | The configuration's 24 parameters |

## SysEx

`F0 00 00 0E 15 <dd> <op> ... F7`, receiver 0x194D, opcode jump table 0x1A0B. `<dd>` must equal
1Dh, the Util MIDI page channel minus 1 (0x168B; channel 0 also gives 0), unless Omni is on
(flag bit 1, which CC 125 sets and CC 124 clears, 0x1809). The editor sends the channel set for the
device. Bytes 0-13 of a program travel as they are; parameters and the 8-bit settings as two
nibbles, high first (encoder 0x1C6E). The program decoder (0x1FFE) refuses the whole message unless
byte 0 < DAh, configuration < 28, every name character >= 20h and every parameter <= its maximum;
the editor limits values before sending.

| Op | Message | Handling |
|---|---|---|
| 00 | `00 InL InR OutL OutR Mod#X AmpX(2) Mod#Y AmpY(2) flags` | Global (0x1DD0): levels <= 100, Mod# <= 122, Amp <= 197; then the dry switch is set from flag bit 2 (0x0400) |
| 01 | `01 <128 x 2 nibbles>` | Program change table (0x1EE3): bit 7 = User bank, bits 0-6 = program |
| 02 | `02 <program>` | Edit buffer (0x1F21) |
| 03 | `03 <128 programs>` | User bank (0x1F62), 7944 bytes |
| 04 | `04 n <program>` | User program n (0x1F7E) |
| 05 | `05 n` | Store the edit buffer into user n (0x1FA4, shows "Program stored from MIDI") |
| 06 | `06 cfg i hi lo` | Parameter change (0x1D3C): applied when cfg is the edit buffer's configuration and the value <= its maximum; ignored while the panel mode byte 58h is 4 or 5 (0x1D9B). The Wedge sends the same message when a slider moves (0x1C8B) |
| 40-43 | request | Global, table, edit buffer, user bank (0x1A20 -> 0x1B07) |
| 7F | request | All four, in the order global, table, user bank, edit buffer (0x1B13) |
| 44 n | request | Read but answered by nothing: 0x1A36 passes 4, not the number, to the transmitter, whose single-program branch (0x1B47) needs bit 7. The editor reads a user program from the 43h dump |

Universal identity request (`F0 7E 7F/dd 06 01 F7`) is answered at 0x1A55 with
`F0 7E dd 06 02 00 00 0E 00 00 15 00 01 00 02 00 F7` (version 1.02).

### Global flags (byte 8 of the System data)

| Bit | Name | Evidence |
|---|---|---|
| 0 | MIDI Thru | MIDI page column "Thru" (OFF/On, 0x46EF); echoes MIDI In at 0x16CB |
| 1 | Omni | CC 125 / 124 (0x1809); SysEx and channel messages skip the channel test (0x1715, 0x196A) |
| 2 | Dry defeat switch | Drives the output switch when the global message arrives (0x1ECE -> 0x0400); the Util "Dry Defeat" page (0x4513) keeps it in step with its own setting |
| 3 | Program edited | Set by any parameter change (0x2276), cleared by store and recall (0x3931, 0x395B); read-only in the editor |
| 4, 5 | (none) | No code reads or writes them |
| 6 | Second effect page shown | Copied from descriptor byte 0Eh for the shown page (0x2225); lights an icon (0x076C); read-only |
| 7 | (not sent) | The transmitter clears it (0x1C05); the receiver puts the old bit 6 there (0x1EB5) |

The MIDI channel (A289h), the PChg mode (A28Eh: OFF, On, tbL), the Send Sysex page choice and the
Dry Defeat page value are front-panel settings that no message carries. Mod# lists Pitch bend
(bnd), Aftertouch (AFt), Note number (not), Velocity (UEL) and Controller 000-119 (display 0x48A9);
Amp is -99..+99 with 00 = off (0x4901). The Util page reaches Mod# 123 and Amp 198 but the
receiver refuses those values, so the editor's lists stop one short. The I/O levels reset to 90
(0x3DF1).

## Channel messages

| Message | Handling |
|---|---|
| Program change | PChg OFF: ignored; On: same number in the current bank; tbL: through the program change table (0x1820) |
| CC 0 | Before a program change (PChg On): 0 = Preset bank, 1-127 = User bank (0x17A8) |
| Mod#X / Mod#Y sources | Pitch bend, aftertouch, note number, velocity or the chosen controller drive two parameters of each configuration (0x174C, 0x1862, 0x1893) |
| CC 124 / 125 | Omni off / on |

## What comes from where

- Firmware: every SysEx message, the program and global layouts, the 28 configurations with their
  page headings, long names, maxima and display texts, the preset and user-reset programs, the
  modulator lists, the flag bits, the identity reply.
- Manual (Wedge reference manual, chapters 3 and 6): the unit names of the LCD icons, the CC 0 bank
  values (they agree with the code), the Mod#X/Y defaults (CC 001 and 007).
- Unverified: everything on hardware. By the code, device byte 7Fh is no broadcast for the Wedge's
  own messages (only the identity request accepts it, 0x1987): outside Omni the channel must match.

## Head Library

Programs are patch kind `effect` (they load only into effects units' programs). The translator
(`alesis-wedge-translate.js`) fills the shared model's `effects` (reverb, delay, modulation/chorus
with time, pre-delay, feedback, rate, depth and level as 0..1 of each parameter's range; delay
times as ms / 2500) and keeps the 38 bytes in `extra` (family `alesis-wedge`), so Wedge to Wedge is
exact. From other sounds it picks a configuration that holds the wanted effects (ROOM+CHORUS,
ROOM+DELAY, LARGE HALL, MONO DELAY...), starts from the first preset that uses it and sets the
decay, pre-delay, delay time, feedback, rate, depth and mixes.
