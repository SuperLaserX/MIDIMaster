# Yamaha DX7 (mark I)

Definition: `js/devices/defs/yamaha-dx7.js` (model config) over the DX family code
(`yamaha-dx.js` builder, `yamaha-dx-voice.js` voice format and parameters, `yamaha-dx-sysex.js`
messages, `yamaha-dx-draw.js` graphics, `yamaha-dx-translate.js` Head Library). Firmware tables:
`yamaha-dx7-fw.js`, generated by `tools/yamaha/dx_fw.py dx7 <ROM> <out>`. Tests:
`tests/yamaha-dx7.test.js`.

**Validated in an emulator of its OS, not on hardware** (no DX7 was connected). Everything below comes
from the v1.8 firmware and Yamaha's published voice format; the editor's messages were then checked
against the DX7's own receiver and transmitter, the OS running in an HD6303 emulator (section
"Emulator check").

## What the firmware does with MIDI

SysEx parser at ED95 (state in 00E7), transmitter E97C/E9BC/EA5C:

| Message | DX7 v1.8 |
|---|---|
| `F0 43 0n 00 01 1B <155> cs F7` | one voice into the edit buffer (2000h); every operator switched on |
| `F0 43 0n 09 20 00 <4096> cs F7` | 32 voices into the internal memory (1000h) |
| `F0 43 0n 01 00 5E <94> cs F7` | TX7 function data (20B0h): sets the function values (routine EFB8, ranges 0-15 scaled to 0-99) and selects the voice in byte 0 |
| bulk data conditions | SYS INFO AVAIL (00F8) on and MEMORY PROTECT INTERNAL (bit 6 of 0088h) off for formats 0 and 9, else MEMORY PROTECTED; the byte count is not checked, the format sets the length. Formats 0 and 9 are written into the edit buffer / internal memory byte by byte as they arrive (EEFD, EF64): a checksum error only shows CHECK SUM ERROR! (EF3E) afterwards, the damaged data stays (format 1 goes through a buffer at 20B0h and is used only with a good checksum) |
| `F0 43 1n 0h pp vv F7` | voice parameter `pp + 128h` (0-155) written into the edit buffer at 2000h + number; only with SYS INFO AVAIL on (EE8B), like the function parameters and the panel buttons below (EECF) |
| `F0 43 1n 08 pp vv F7` | pp 64-77: function parameter (RAM addresses at F028); pp 0-41: the panel button `pp` pressed (vv > 0) or released (routines C92D/C970) |
| `F0 43 2n ...` (dump request) | **ignored**: sub-status 2 is rejected at EDBC. The DX7 answers no requests |
| `Cn pp` | voice `pp & 3Fh`: 0-31 internal, 32-63 cartridge (if inserted) (ED47) |
| sent | on voice select with SYS INFO AVAIL: the edit buffer as one voice (E9BC; otherwise a program change, EB4E); while editing: parameter changes (group 0 voice, group 2 function, EA5C/EA7E); FUNCTION 8 > MIDI TRANSMIT ?: the 32 internal voices (EA15) |

The SysEx channel is the DX7's MIDI channel (receive 2573h, transmit 2574h); the editor uses the
device's MIDI channel.

## Voice (VCED, 155 bytes + operator on/off)

The firmware's edit parameter table at F551 (maximum, VCED offset; offsets 7Eh and up are
voice-wide, lower ones per operator) and its label table at F4F9 give every label and range; the
display code loads four labels itself (ALGORITHM SELECT F11A, F COARSE F145, F FINE F14F,
OSC DETUNE F2ED). Operators are stored OP6 first, 21 bytes each.

| Byte (per operator) | Label (firmware) | Range | Display |
|---|---|---|---|
| 0-3 | EG RATE 1-4 (FA7C) | 0-99 | number; graph (drag the points) |
| 4-7 | EG LEVEL 1-4 (FA87) | 0-99 | number; graph |
| 8 | BREAK POINT (FA92) | 0-99 | A-1 .. C8 (note table F5A9) |
| 9, 10 | L / R SCALE DEPTH (FAB9, FAC7) | 0-99 | number; scaling graph |
| 11, 12 | L / R KEY SCALE (FA9F, FAAC) | 0-3 | -LIN -EXP +EXP +LIN (F5C1) |
| 13 | RATE SCALING (FAD5) | 0-7 | |
| 14 | A MOD SENS. (FA41) | 0-3 | |
| 15 | KEY VELOCITY (FAF0) | 0-7 | |
| 16 | OUTPUT LEVEL (FAE3) | 0-99 | |

Frequency display (F145, F1B6): ratio = coarse x (100 + fine) / 100, coarse 0 = 0.50 + fine/2
(integer, so 0.50-0.99); fixed = the four digits of table F21D (one entry per FINE value, e.g.
2716 for 44 — the table's own values) with the point after (coarse mod 4) + 1 digits, then Hz
(1.000Hz .. 9772 Hz). VOICE INIT (D16B) and CARTRIDGE FORMAT use the packed voice at C25C: all
EG rates 99, levels 99 99 99 0, OP1 output 99, others 0, BREAK POINT A-1, P EG levels 50,
algorithm 1, LFO SPEED 35, P MOD SENS. 3, MIDDLE C C3, "INIT VOICE".

Packed format (VMEM, 128 bytes, the internal memory and the 32-voice bulk): per operator 17 bytes
(R1-4, L1-4, BP, LD, RD, RC<<2|LC, PD<<3|RS, KVS<<2|AMS, TL, PC<<1|PM, PF), then P EG, ALG,
OKS<<3|FB, LFO speed/delay/PMD/AMD, PMS<<4|WAVE<<1|SYNC, transpose, name.

## Function (group 2, parameters 64-77)

POLY/MONO (POLY MODE / MONO MODE), P BEND RANGE 0-12, P BEND STEP 0-12, PORTAMENTO MODE (poly:
SUS-KEY P RETAIN / FOLLOW, mono: FINGERED PORTA / FULL TIME PORTA: table F847 indexed by
mono x 2 + mode, F7BA), GLISSANDO OFF/ON, PORTA TIME 0-99, and for WHEEL, FOOT, BREATH and AFTER
(F813): RANGE 0-99 and the PITCH / AMP / EG B. assign bits. The DX7 cannot send them on request;
the editor keeps its own values (all 0 at first, which is what the firmware sets when its memory
holds invalid ones, C605) and receives the ones changed on the panel.

## Editor

- **Voice** page: a Voice section (Algorithm card with the diagram, the 32 algorithms to click,
  operator on/off; LFO; Pitch EG graph; MIDDLE C) and OP1-OP6 sections (oscillator, EG graph,
  keyboard level scaling with its curve, output and sensitivity). Every change is a parameter
  change; Send to edit buffer sends the single-voice bulk.
- **Internal voices**: the editor keeps a copy of the 32 voices (from MIDI TRANSMIT, picked up
  by Get 32 voices, or opened from a file). Edit loads a voice from the copy; Play sends a
  program change; Store puts the voice into the copy and sends all 32 (only once the copy came
  from the unit, so a file never overwrites the DX7's voices unasked). Send bank / Bank file...
  send, open and save the copy.
- **Function** page: parameters 64-77.
- Branch Library and Head Library: a 32-voice bulk becomes 32 voices, a single-voice bulk one.
- Head Library translator (family `yamaha-dx`): exact between DX models; from other families on
  algorithm 5 with a report (`yamaha-dx-translate.js` explains the mapping).

## Emulator check

`tools/yamaha/check_editor.mjs dx7` (test: `tests/yamaha-dx7.test.js`, skipped without the firmware)
runs the v1.8 OS in `tools/yamaha/dx_emu.mjs` (HD6303 core `tools/yamaha/hd6303.mjs`: on-chip timer and
serial port, MIDI at 31250 baud) from its reset vector, with RAM 1000h-27FFh, the 8255 at 2800h (LCD on
ports A/B, latched on E falling; port C bit 7 = LCD busy) and the other I/O as write-only latches. The
editor's own messages (from the definition: sendParam, sendAll, slots.store / recall, receive) go in
through the serial port; results are read from the DX7's RAM and from what its own transmitter sends.
17 checks, all equal:

- boot to the voice screen; SYS INFO AVAIL off: a parameter change and a voice bulk ignored; MEMORY
  PROTECT INTERNAL on: the voice bulk refused (MEMORY PROTECTED);
- Send to edit buffer (format 0 + operator switches): edit buffer 2000h-209Bh equal;
- every voice parameter as a live edit (161 changes, twice with other values), the name by parameter
  changes 145-154, every parameter at its minimum and maximum sent whole: edit buffer equal each time;
- Store into a slot of the editor's copy (factory ROM1 A + one voice): internal memory 1000h equal; all
  32 voices selected by program change: the DX7's own unpacking equals the editor's (vmemToVced), and
  the voice it sends on each program change (SYS INFO AVAIL) reads back equal in the editor;
- MIDI TRANSMIT from the panel (FUNCTION, button 8 to MIDI TRANSMIT ?, YES; driven by panel-button
  parameter changes): the 32 voices it sends equal the editor's copy;
- a panel edit (YES): the parameter change it sends, taken by the editor, equals the edit buffer;
- every function parameter (64-77) in its RAM place (table F028);
- a wrong checksum: CHECK SUM ERROR! with the bytes kept (see the table above); another channel ignored.

Found by the check: the DX7 takes parameter changes only with SYS INFO AVAIL on (the editor's note says
so); the MIDI parser takes one data byte per main-loop pass from its 380-byte ring (23F4h), so it lags
behind a fast stream but loses nothing (the editor's 60 ms gap is ample).

## Not covered / to check on a unit

- The DX7 has no dump request: reading needs SYS INFO AVAIL and the panel (voice select, MIDI
  TRANSMIT). Cartridge voices cannot be sent over MIDI by the DX7 (MIDI TRANSMIT sends the
  internal memory).
- Panel-button remote (group 2, 0-41) is documented, not offered as controls.
- Cartridge voices (program changes 32-63) are not covered by the emulator check (no cartridge
  emulated). The analog side (sound, battery, keyboard) is outside what MIDI reaches.
