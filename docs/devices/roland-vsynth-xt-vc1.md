# Roland V-Synth XT VC-1 (D-50)

The V-Synth XT's VC-1 engine: the D-50's MIDI implementation as the XT's VC-1 application (OS 2.02,
VAPP3) answers it. The full write-up (firmware, address map, range table, undocumented SysEx) is
in [roland-vsynth-xt.md](roland-vsynth-xt.md), section "VC-1 engine (D-50)".

What the editor covers:

- The 448-byte patch: patch block, upper and lower tone common, four partials. Every byte has the
  firmware's range, and names and value displays come from the VC-1's screen strings. That
  includes the VC-1's six extra patch bytes (chase, portamento and separate switches, MIDI Tx bank
  select, tone and partial select).
- The temporary patch (00 00 00), with each change sent as it is made; the 64 patches 11-88 of the
  bank selected on the VC-1 (02 00 00 + n × 1C0h); reverb data 17-32 (03 60 00) in the complete
  dump.
- Rename actions for the patch name (18 characters) and both tone names (10), in the D-50
  character set.
- D-50 SysEx files (one-way DT1, or DAT from a handshake transfer) import into the Branch Library and
  the Head Library as VC-1 patches.

Checked on the unit (2026-11-24, device ID 00): whole-patch writes, single parameters, a VC-1-only
byte, renames, an out-of-range value (refused), a D-50 bulk-dump file and JP-8080 and V-Synth
patches through the translator all read back as sent; the temporary patch was restored afterwards.
A bank read takes about 21 s.

**Bank select** (firmware, VAPP3 `FUN_89313B70`; checked by the user 2026-11-25): the VC-1 stores
CC 0 and CC 32 per part and takes a program change only with MSB **87** and LSB **0-13** (and below
64): patch = (program & 3Fh | LSB << 6) + 1, so LSB 0-7 = the internal banks, 8-13 = the presets,
program 0-63 = patches 11-88. The VC-1 shows them as Int1-Int8 and Pre1-Pre6; the bank list reads
Internal 1-8 and Preset 1-6, the slots Int1-11 ... Pre6-88. Pre2-11 played "Brass Tacks", factory
patch 65: **the preset banks are the 384 factory patches in order**, so their names come from the
firmware (`PRESET_NAMES`, generated with the other tables).

SysEx reaches the patch memory of the bank selected on the VC-1 ("Current bank", 02 00 00). The
editor follows which bank that is: **Play** in a bank selects it, makes it current and reads its 64
names in the background (kept under both entries); **Edit** in a bank that is not current selects
the patch and reads the temporary patch (the VC-1 then plays it); Edit, Read names and Store in the
current bank go by address (Store only into internal banks). On connect the current bank's names
are read and matched against the presets' names and the internal banks' names read before (the
editor remembers names per device, and the last bank it selected), so the list says which bank is
current. The factory Internal 1-6 are copies of Preset 1-6 (Internal 7-8 hold "Initial patch"), so
names alone are often ambiguous: the list then says e.g. "Current bank (Preset 1 or a copy?)" until
a Play or Edit selects a bank.

Checked on the unit (2026-11-25): from Int1-11, bank select 87/9 + program 0 made patch memory
(02 00 00) answer Pre2's patches ("Brass Tacks", "A Bright Day"): **SysEx follows the bank chosen by
bank select**. In the editor: after connect the list said "Preset 1 or a copy?"; Play on Int1-11
made it "Current bank (Internal 1)" and read Internal 1's names. The temporary patch was put back
byte for byte each time.

The VC-1's user banks are also files on the XT's drive (`VC1_I1.P10` ... `VC1_I8.P10`, 36 944
bytes): a 16-character date stamp, the 64 patches in the 448-byte patch-memory layout, the reverb
data 17-32 and 64 records of 35 bytes. The Head Library imports them (64 patches each, labelled
"Int1-11" ...), also from a whole drive image; the patches are byte for byte what the unit answers
for the same bank. **Save bank .P10** (Patch page) reads the current bank and its reverb data from
the VC-1 and writes `VC1_In.P10` (the 35-byte records as in every factory file, today's date in the
stamp); all eight factory files rewrite byte for byte.
